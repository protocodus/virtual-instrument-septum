# Dynamic-filter estimator control

**Envelope movement does not explain an apparent first-stage damping change
from 2.0 to 1.2 in the tested recipe.** An independent engine-rendering control
recovers the known damping of both production and candidate filters. The
small remaining movement bias increases estimated damping.

This validates the measurement method in
[analyze_deepsonic_filter.py](../../../Tools/analyze_deepsonic_filter.py).
It is a synthetic control using known DSP, not another hardware measurement.
No shipping DSP was modified for this check.

## Independent signal generation

A standalone C++ fixture renders the actual engine, including its oscillator,
moving TPT filter, sample/control scheduling, amplitude envelope, overdrive
bypass latency and analog output model. The fixture is separate from the
estimator and never constructs audio from the estimator's response formula.

Five notes, MIDI 24, 36, 29, 31 and 57, each last one second with a one-second
gap. One saw oscillator feeds LP12 or LP24 at resonance zero. Filter KEY FOLLOW
is 100; cutoff 34, envelope depth 21 and decay 63 give an initial cutoff of
`7.8230638269 × f0` and a `1.0138693908 s` decay linear in envelope control.
Attack is zero and sustain is zero for the moving case. Sustaining the filter
envelope at 127 provides the stationary control. All LFO depths, velocity
sensitivities and effect switches are zero/off. AMP level 50 keeps levels low.

The production source snapshot supplies first/second-stage damping `[2, 1.2]`.
A separate positive control sets `[1.2, 1.2]` through the public calibration
API. Each has stationary and moving variants at both slopes: eight WAVs.

The target estimator's `measure`, `fit_cutoff`, masks and local response model
are applied without changing their equations. Windows are centered 80, 160,
240 and 320 ms after onset and include the engine's 93-sample latency. Each
uses 80 ms width, with ±10 ms shifts and 100 ms width as sensitivity checks.
Only MIDI 36's nominal windows recover shared first/second-stage damping;
each window retains its own nuisance cutoff. The other four notes validate
the result. LP12 identifies the first stage separately, preventing the two
LP24 stages from becoming an interchangeable pair.

## Recovered damping

| Generated truth | Envelope | Recovered first stage | Recovered second stage |
| --- | --- | ---: | ---: |
| 2.0, 1.2 | Stationary | 1.99929 | 1.20078 |
| 2.0, 1.2 | Moving | 2.00440 | 1.22394 |
| 1.2, 1.2 | Stationary | 1.20041 | 1.19999 |
| 1.2, 1.2 | Moving | 1.21291 | 1.22391 |

The first-stage dynamic bias is about +0.0044 for the production generator,
far smaller than the proposed −0.8 change. The candidate's first-stage bias
is about +0.0129. The second-stage moving-filter bias is about +0.024 in both
cases. Small nonstationarity, oscillator bandlimiting and the output response
remain in this end-to-end control.

For moving signals generated by `[2, 1.2]`, the withheld-note harmonic errors
are:

| Slope | Correct `[2, 1.2]` model, H2–H8 | Incorrect `[1.2, 1.2]` model, H2–H8 | Correct model, withheld H9–H16 | Incorrect model, withheld H9–H16 |
| --- | ---: | ---: | ---: | ---: |
| LP12 | 0.0093 dB | 1.4274 dB | 0.0445 dB | 3.1101 dB |
| LP24 | 0.0725 dB | 1.5717 dB | 0.1168 dB | 2.8736 dB |

The correct model wins across every tested timing/window variant. The moving
positive control also distinguishes the alternatives: its `[1.2, 1.2]` model
has lower-harmonic validation errors 0.0349/0.1131 dB at LP12/LP24, versus
1.2253/1.4181 dB using `[2, 1.2]`.

The maximum local harmonic-fit residual fraction is `7.08e-5` for moving
production and `1.96e-4` for the moving positive control. All eight WAVs are
finite. Numerical recovery is precise enough to distinguish these particular
damping hypotheses under this recipe.

## Limits and provenance

This rules out the tested envelope-motion bias as the cause of a large
apparent damping reduction. It does not independently establish the hardware
patch, isolated source spectrum, recorded processing or every filter shape.
The modeled decay is approximately one second; a substantially faster or
different real envelope should receive its own control before reusing this
bound. No free recording EQ or per-harmonic gains were fitted.

The [compact measurement record](filter-estimator-bias-2026-09-15.json)
retains known settings, source/binary/audio hashes, recovered parameters,
nominal and sensitivity metrics, and the complete independent C++/Python
fixture source. The full local artifact directory is
`build-fidelity/hardware-benchmark/filter-estimator-bias/`, containing the
frozen DSP, `render.cpp`, `analyze.py`, eight WAVs and all measured windows.
The original source snapshot is essential when reproducing the production
control after changing the shipping damping curve.

From that artifact directory, rendering is reproduced with:

```sh
c++ -std=c++20 -O2 -fno-fast-math render.cpp DSP/SeptumEngine.cpp -o render
./render .
OPENBLAS_NUM_THREADS=1 python3 analyze.py
```
